# 九键拼音

Android 默认使用电话键盘布局：ABC→2、DEF→3、GHI→4、JKL→5、MNO→6、PQRS→7、TUV→8、WXYZ→9。
全拼的每个字母都对应一次数字按键，ü 沿用词库的 v。例如 nihao 对应 64426；64 同时可能读成 ni 或 mi。

输入法壳只发送数字和用户确认的拼音，解码、候选、排序、分段上屏全部在 Core。
`Engine::set_nine_key(true)` 按当前词库建立数字索引，关闭时清空旧组句并恢复全拼路径。
词索引按编码排序，完整匹配和前缀匹配通过二分定位，不枚举指数增长的字母组合。
只有最后一个音节可以补全；已输入部分之后不自动补出另一个音节。

词候选先按覆盖的输入长度排序，再按是否完整命中、既有选择权重、模糊音改动数和词频排序。
完整数字串还会进入有界整句搜索，复用 Core 的词频、语言模型和个人 n-gram；未装语言模型时使用词频回退。
目前不提供九键简拼、云端补全或神经模型重排。实际 Android 包只装随包词库与英译表，没有用户词频持久化。

可确认的下一音节来自 Core 的合法拼音表。已确认的音节作为候选和整句的前缀约束，避免 ni/mi 等同码音节混淆。
选择短候选只消耗它对应的数字和已经确认的音节，后半段继续出候选；退格后重新消歧。
词索引是开启方案时的快照，动态修改词库或新增用户词后，需要关闭再开启以刷新索引。

九键支持三组双向鼻音模糊：`an/ang`、`en/eng`、`in/ing`，默认全部关闭；全拼使用原有的 `FuzzyRules`。
调用 `Engine::set_fuzzy` 会重建活动九键索引并清除查询缓存。每个词只保留一份原词条，模糊写法通过编码、词条编号和音节位掩码建立别名。
每词最多 64 个编码记录，优先覆盖各位置单独变化，再补组合变化；极长词的所有多位置组合不保证穷举。
同码时原读音优先，整句为每个变化音节计入模糊代价。原读音保存在 `Candidate.syllables`；模糊命中的实际输入读音保存在 `Candidate.reading`。
预编辑、音节锁定与分段上屏消耗按实际输入读音计算。例如输入 `xinghao` 的数字码后选“新”，只能消耗 `xing`，`hao` 继续出候选。

查询输入长度上限为 64，词候选上限为 500，整句 beam 为 5，每个片段最多 24 个词，最多显示 3 个整句。
Android 快照最多提供 60 个候选，候选栏可以横向滑动。候选序号对应同一份 JNI 查询快照，防止点击时重新查询改变顺序。

可用 `cargo run -p qingjian-cli -- --nine-key --dict assets/lexicon/dict.tsv 64426 64 94664486` 检查
“你好”、“你/米”和“中国”；同音、同数字的整句可能有多个结果，仍应由用户选择。
