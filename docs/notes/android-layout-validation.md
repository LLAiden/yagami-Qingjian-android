# Android 0.2.4–0.2.7 布局与模式验收

日期：2026-10-03。最终版本：0.2.7-preview / versionCode 14。需求见 [已确认产品范围](../plan/android-product-optimization.md)。

## 本轮修改

- 用户最终确认顶栏空闲显示工具、输入时原位显示候选与英语释义，仅保留收起工具按钮；九键组合放在左侧滚动栏，键盘整体高度与按键位置保持不变。
- 去除输入区重复工具与模式入口，符号分页使用上一页 / 下一页；动作键强调背景保留统一 2dp 视觉间隔。
- 工具栏从左到右为全选、编辑、Google 验证器、Bitwarden 密码管理器、剪贴板、收起。仅显示圆底居中图标，以固定 48dp 宽度靠右排列，辅助功能名称保留。
- Android 输入模式精简为拼音九键、英语全键盘、数字九键；中文全拼切换移除，旧方案偏好不影响布局。
- 所有模式统一英文半角标点，符号页提供两组 ASCII 符号，返回原键盘。
- 拼音底行中央三列为 `123 | 空格 | EN`，等宽且每键仅占一列；动作键仍在最右下角。
- 英语空格位于键盘中线，左侧紧邻数字、右侧紧邻中文切换；Shift 一次单字母大写，两次锁定大写，再次解除；临时数字与符号页保留锁定状态。
- 数字底行中央为 `EN | 0 | 拼音`，空格在左侧功能列。菜单图标最终为 18dp，36dp 圆底和 48dp 点击宽度保持不变。
- 同栏外部应用按钮使用系统应用启动入口；未安装时提示且保留拼音，启动已安装应用前提交当前拼音。
- 切换数字页先提交拼音；保留英语释义、鼻音、宽退格、最右下角动作及之前的输入修复。

## 自查与复查

修改前在 0.2.3 上运行最初的四项需求用例，四项均失败：空闲候选可见、页面顺序不符、中文全拼入口仍在、转数字未提交拼音。

首次改为直接改变窗口高度后，实际触摸回放发现候选显隐时窗口与输入坐标短暂不同步：输入下一键会误触空格，提前提交“哦”等候选。辅助功能缓存清理不足以解决，未以等待更久掩盖问题。
0.2.4–0.2.6 固定 IME 窗口测量高度，以透明顶部和实际内容 / 触摸 insets 隐藏空闲候选区域。按键位置稳定，但候选与拼音出现仍向上增加可见高度；按用户最新反馈，0.2.7 改为共享固定顶栏与左侧拼音栏，去除透明预留区，整体高度稳定。

0.2.4 新增 `KeyboardLayoutTest` 七项全部通过，用时 28.079 秒；0.2.5 更新同栏断言，最终用例为：

1. 空闲候选隐藏，输入和选词后按键屏幕坐标不变。
2. 0.2.7 共享顶栏切换后根窗口、顶栏、输入区边界均不变，英译可见，其他工具隐藏、收起保留。
3. 拼音九键 → 英语全键盘 → 数字九键 → 英语 → 拼音，结果逐字一致。
4. 输入 `64426` 转数字先得到“你好”，返回仍为拼音九键。
5. 六个菜单图标在同一行，顺序与要求一致，48dp 固定点击宽度、靠右布局。
6. 中文、英文、数字切换过程中英文标点逐字一致。
7. 使用输入前的固定按键坐标，连续十次输入 `64426` 并选词，最终恰为十次“你好”。
8. 拼音数字、空格、英语三个底行键等宽，空格宽度与九宫格单键相同；数字页确认 `EN | 0 | 拼音` 和中线；完整切换并输入后得到 `10a hi`。
9. 宿主数字输入框也能按 EN / 拼音进入所选文字键盘，返回数字后输入 `10` 逐字一致。

新增 `KeyboardEnglishTest` 两项检查单次大写 / 锁定 / 解除、空格居中与跨临时面板锁定；`KeyboardPasswordManagerTest` 两项确认未安装外部应用时保留拼音和键盘。

导航切换的早期回归出现“键盘未显示”或旧节点越过安全边界的误报。检查系统窗口和实际 insets 后，测试改为清理辅助功能缓存、在原等待期限内等待新窗口稳定；减少重复 showSoftInput 对窗口动画的干扰。导航模式切换连续五轮通过，生产代码未增加延时或重试。setUp 失败时显式关闭调试 Activity，避免 JUnit 3 跳过 tearDown 后阻塞后续测试。

## 环境与验证范围

自动化环境为 Android 15 / API 35 ARM64 模拟器，Pixel 6，1080×2400，密度 2.625，在真实系统 IME 窗口注入触摸事件。
JNI 两项测试、fmt 和 JNI clippy 通过；Core 输入算法本轮未修改，沿用 0.2.3 的 313 项通过记录。双 ABI JNI 重建，Debug、AndroidTest、未签名 Release 构建成功，lint 无错误（Debug 16 / Release 14 条既有警告）。

0.2.4 全量 Android 回归 60 项通过，用时 257.507 秒：已有 53 项随三种模式调整使用步骤，加本轮 7 项布局回归。快速 / 双指 / 输入框重启共 1,320 个数字逐字一致，数字模式的同输入框重启仍能保留按下中的按键。

0.2.5 全量 Android 回归 65 项通过，用时 267.130 秒。0.2.6 初次英语底行与数字模式针对性回归 12 项通过，用时 47.223 秒，之后按最终确认调整数字底行顺序并继续全量验证。
0.2.6 / versionCode 13 全量 65 项通过，用时 269.966 秒。追加真实数字输入框的语言切换用例后，复现 EN 仍停留数字页：输入框的默认类型覆盖了用户选择。修复后以 versionCode 14 继续回归；没有放宽该用例的等待或删去断言。

0.2.7 针对性布局 / 英语 / 图标 / 外部应用回归 19 项通过，用时 69.853 秒。全量 66 项的第一轮暴露展开列表分段选词后未回到键盘的问题，已修复。下一轮 65 项通过，1 项在连续设置更新后重复读取节点的瞬间读到空值；测试改为复用刚找到的节点，并针对性复查鼻音、展开候选长按与各面板收起。
Core 313 项与 JNI 2 项重新运行通过。80 个预热后逐键样本：JNI + JSON p95 0.619ms，更新 / 布局 / 绘制 p95 2.728ms；此分段耗时不代表手机端到端触摸延迟。APK zipalign 16KB 检查通过。

小米 25053RT47C / Android 16 已依次覆盖升级至 0.2.4 / versionCode 11、0.2.5 / versionCode 12、0.2.6 / versionCode 13、0.2.7 / versionCode 14。每次读取包信息确认版本，预览输入法已启用并选中，调试输入验收页已打开；预览签名沿用上一版本。真实应用手动体验由用户继续进行。
