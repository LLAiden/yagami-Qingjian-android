# Android 输入法产品优化需求

日期：2026-10-03。基线：0.2.3-preview。面向下一阶段迭代，不代表本文中的能力已经实现。

## 产品目标与决策顺序

把 Yagami 做成可以每天用于聊天、搜索、填写表单的输入法，再用随候选显示的英语释义形成特色。
优先级依次为：不丢字、不误删 → 候选准确、输入流畅 → 按键好点、功能好找 → 个性化与学习。
新增学习功能不能阻塞输入或抢走点击区域；用户主动开启的云功能才能发送数据。

核心用户任务：第一次安装后打出一句话；九键连续输入并消歧；中文、英文、数字和符号切换；修改与粘贴；随时收起；查看英语释义。
以“完成一个任务需要多少次操作、失败后能否恢复”评价体验，不以增加多少菜单或图标评价。

## 本次问题的交付范围

| 用户问题 | 0.2.3 已实现 | 仍需验证或继续优化 |
|---|---|---|
| UI 太丑 | 统一浅色 / 深色配色、文字层级、细边框、圆角、按下反馈；同步启用向导样式 | 外观偏好需由实际用户评估；尚未做用户可用性测试 |
| 输入没有对应英语 | 中文候选下直接显示已有英语释义；展开后同样显示；长按查看释义提示 | 释义覆盖率、长句阅读、是否显示释义的开关 |
| 拼音选项相连 | 独立背景、6dp 间隔、可点击范围 | 极窄屏与系统大字体的专项验收 |
| 全键盘删除太小 | 删除键宽于字母键，标准竖屏达到 48dp 触摸尺寸 | 横屏及最小高度下的误触测试 |
| 九键 1–9 未居中 | 中央九宫格与对称功能列；数字在各键几何中心、字母提示独立 | 单手模式、左右手偏好与折叠屏 |
| 缺少图标 | 键盘、剪贴板、编辑、全选、收起、退格、回车等统一矢量图标；保留动作文字和无障碍名称 | TalkBack 真正完成输入任务的验收 |
| 快速输入漏字 | 修复按键间隙的触摸丢失、同一输入框重启取消按下中的按键；复现 123456 → 12356 后加入回归 | 模拟器压力回放通过后仍需在用户原应用与手机验收 |
| 感觉卡顿 | 候选分批构建、共用样式、复用未变化视图，串行执行所有命令并省去过期的纯查询 | 已测模拟器局部界面开销，低端真机端到端延迟、启动和内存仍需建立基线 |
| SP 更换为 MMKV | MMKV 2.4.2，自动迁移设置和剪贴板；迁移完成清旧副本，避免历史复活 | 真机跨版本覆盖升级与故障恢复 |
| 前后鼻音模糊 | 三组独立开关，双向、默认关闭，九键与全拼均支持；分段上屏保留剩余输入 | 声母等更多模糊设置与精度评估 |
| 动作键位置 | 搜索 / 发送 / 换行 / 完成在最右下角，按应用动作切换文字 | 真实应用兼容矩阵 |

“暂无释义”表示当前数据没有该词，不能通过编造翻译掩盖缺失。点候选仍只上屏中文。
本次没有更换词库、接入在线翻译、增加语音或滑动输入。

## P0：成为可靠的日常输入法

这些是稳定版发布门槛，先安排，未完成时继续标记预览版。

| 编号 | 优化需求与用户价值 | 可验收条件 |
|---|---|---|
| R01 | 建立厂商真机与真实应用兼容矩阵，确认聊天、搜索、表单确实可用 | 至少覆盖小米、OPPO / vivo、三星或 Pixel 中三类手机；记录系统和应用版本；微信、QQ、浏览器、系统短信分别完成中文整句、选区删除、粘贴、发送 / 搜索、切焦点、旋转和收起 |
| R02 | 将“不丢字、不重复上屏、不误删”作为质量红线 | 回放至少 1,000 次快速输入、选词、全选、emoji 退格、长按滑出、切页及 restartInput 组合事件，正文与预期逐字相同；所有失败有可复现用例；发布前无未解决的严重数据损失问题 |
| R03 | 建立输入延迟、冷启动与内存基线，定位低端机卡顿 | 在指定的低端和中端 ARM64 真机记录 30 次冷 / 热启动、逐键候选 P50 / P95 与内存峰值；初始目标为热启动 P95 ≤200ms、冷启动 ≤800ms、逐键候选 P95 ≤100ms；未达到时先分析，不把目标写成已测成绩 |
| R04 | 把候选准确率纳入迭代验收，先修九键常见歧义 | 建立有许可来源的 500 常用词、200 日常短句、100 姓名地名、100 中英混输的冻结测试集，分九键 / 全拼记录首选率和前五命中率；每次改排序不得降低总成绩，重点失败类别须有提升与逐例说明 |
| R05 | 安全接入已有的本地用户词频与用户词能力，让常用词越用越靠前 | 用户开启后，同码多次选择能提升该词排序；重启 / 升级后保留；可查看并清除学习数据；密码、敏感输入不学习、不记正文；Android 仅装配 Core 能力，不自行排序 |
| R06 | 保证隐私行为可理解、可控制 | 提供剪贴板历史与本地学习的独立开关、保留时长选项和清除入口；关闭历史后新复制不持久化，历史不可意外重建；敏感框不出现普通历史；界面说明数据位置与用途 |
| R07 | 建立可重复的安装、覆盖升级与回退验证 | 固定发布签名、版本递增；连续升级两个版本后设置和固定剪贴板保留；缺失 / 损坏数据能恢复输入；APK 与对应源码、许可、校验值一起交付；真机验收后再发布稳定渠道 |

R01 当前未完成：此前连接的小米 Android 16 手机拒绝 USB 安装，错误为 `INSTALL_FAILED_USER_RESTRICTED`；没有把模拟器结果计为真机成绩。
R03 的数字是需求目标，R04 的数据集是待建设任务。已有模拟器界面更新 / 布局 / 软件绘制段的测量：P95 约 10.6ms → 3.0ms；这不能替代真机端到端、启动、内存与准确率基线。测量方法与限制见 [验收记录](../notes/android-visual-validation.md)。

## P1：减少误触和操作成本

| 编号 | 优化需求与交互要求 | 可验收条件 |
|---|---|---|
| U01 | 做一次以任务为中心的可用性测试，验证新 UI 是否真好用 | 邀请至少 5 名九键、3 名全键盘用户；不给口头提示完成输入、纠错、复制粘贴、切换布局、收起五类任务；记录耗时、误触和找不到入口的位置；高频失败进入下一轮修复 |
| U02 | 优化按键触控、震动与声音；可关闭并保存偏好 | 删除、收起、切换等重要功能在常用竖屏达到至少 48×48dp；点击反馈与真正触发一致；滑出长按删除立即停止；震动强度支持关闭 / 轻 / 标准，不因绘制或候选刷新重复触发 |
| U03 | 提供候选字号与“显示英语释义”开关 | 开关后当前输入和选词编号保持一致；相同配置内输入过程中键位不跳动；中文仍清楚，缺失释义不抢占首选；长释义有可停留、可滚动的详情视图 |
| U04 | 调整候选与拼音的阅读层级，方便找到首选和已确认音节 | 高亮只表达首选或确认状态；长词不与邻词挤连；读音选项有间距与选中反馈；同码锁定后能看清已确认音节、剩余输入及撤销方式 |
| U05 | 增加空格滑动光标和受限的撤销，降低纠错成本 | 轻滑可逐字符移动且不误上屏；按住后拖动与单击明确区分；提供一次撤销最近上屏 / 删除；宿主正文已被修改时停止撤销，避免覆盖新文本 |
| U06 | 增加单手模式与更细的高度调整 | 可选择左 / 右手，主键盘居中于单手区域；全选、退格、收起仍可达；恢复标准模式一步完成；不同方向分别保存高度并限制在安全范围 |
| U07 | 补齐常用符号、成对标点、最近使用 emoji 和长按数字 | 长按字母 / 九键输入数字有清晰预览，松手只提交一次；全角 / 半角随输入场景可选；电话号码、小数和负号仍正确；符号页返回原布局和原输入 |
| U08 | 提供独立设置页、启用状态检查和可操作的帮助 | 启用、设为当前输入法两个状态分别展示；未完成时有一步入口；用户可以在不打开键盘时调整外观和隐私；“恢复默认”明确说明清除范围，不清正文 |
| U09 | 覆盖无障碍、小屏、大字体与横屏 | 320dp、360dp、412dp 宽度，字体 1.0 / 1.3 / 2.0 倍均无不可达的关键操作；TalkBack 能找到并激活删除、候选、收起；横屏空间不足时重新排版，不能简单裁掉释义或按钮 |
| U10 | 允许配置顶栏快捷入口，降低重复菜单操作 | 常用操作最多一次点击；“设置”在编辑面板与独立设置页中可找到；收起始终保留；可以恢复默认，配置升级后不丢失 |

48dp 是 Android 的交互目标建议，见 [官方无障碍指南](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views)。
手机全键盘字母键无法在窄屏同时达到这个宽度；应通过合理行距、扩大重要功能键、触摸区域和误触实测改善，不能把“所有字母 48dp”写成不可能的验收要求。

## P1：输入质量与英语学习特色

| 编号 | 优化需求 | 可验收条件 |
|---|---|---|
| I01 | 常用短语、姓名和专业词的词库扩展 | 用户可新增、导入、删除自己的短语；输入码与排序走 Core；导入前显示条数与错误，保留数据许可；重启和升级保留 |
| I02 | 在已交付的三组鼻音基础上，按需加入声母模糊、拼写纠错与中英混输能力 | 各项有独立设置与明确样例；开启后验证常见误拼，关闭后恢复原行为；姓名、缩写、URL 和英文标识符不被强行改为中文 |
| I03 | 整句输入后能分段改词，避免整句重敲 | 选择已输入音节后只替换对应片段；确认过的部分有状态显示；退格和取消不会重复提交；原始拼音回车直输仍可用 |
| L01 | 提升英语释义覆盖与准确性 | 用 R04 常用词集合统计有释义比例，抽样至少 100 词做人工语义核对；区分词性、多个义项与词组；有来源、可反馈错误，离线仍可用 |
| L02 | 从查看释义到主动学习，避免学习干扰输入 | 可收藏词汇、查看释义详情和可选发音；长按学习操作不意外上屏；发音只在主动点击时播放；统计和生词本能关闭、导出、清除 |
| L03 | 自定义学习负担 | 可关闭英语行或只显示首选释义；两种模式独立保存；无学习需求时仍是一款完整的输入法，不持续提示开启 |

本阶段只并列显示一种学习语言，沿用 Core 的主语言 / 学习语言边界。英语词义不能仅依据当前拼音臆测；在线补译必须另设主动授权与离线回退。

## P2：基础体验稳定后的扩展

| 编号 | 候选需求 | 进入开发的前提与验收方向 |
|---|---|---|
| E01 | 语音输入 | 有稳定的文本输入基线；用户点击后请求麦克风权限；清楚说明本地 / 在线处理方式；拒绝权限仍可正常打字；可编辑识别结果，网络失败不丢现有正文 |
| E02 | 滑动输入 | 先验证九键 / 全键盘触控质量；建立滑动识别正确率与误触数据集；开关关闭后完全保留普通点击行为 |
| E03 | 可选跨设备词库备份 | 先提供本地导入导出；用户主动开启同步，清楚展示范围与冲突处理；密码输入与剪贴板默认不纳入同步 |
| E04 | 主题、皮肤与更丰富 emoji | 保持功能键位置和对比度；皮肤不破坏触摸尺寸；外部资源有许可，先验证深浅主题与性能 |

语音、滑动与云能力属于不同规模的后续项目，需要专项方案与验证，不能用一个入口图标视为完成。

## 衡量方法与迭代安排

所有指标先采集基线，再设改进目标。测试记录存本地；用户正文与学习数据不默认用于遥测。

| 指标 | 采集方式 | 决策用途 |
|---|---|---|
| 首次成功输入率、完成启用时间 | 可用性测试中计数与计时 | 判断安装引导是否需要改造 |
| 首选率、前五命中率、平均选词次数 | 固定词句集离线回放，九键与全拼分别报告 | 判断词库、消歧、排序改动是否有效 |
| 输入后退格率、关键功能误触次数 | 经同意的任务观察或测试脚本 | 判断新布局、单手和震动是否改善效率 |
| 候选 P95、键盘冷 / 热启动、内存峰值 | 指定真机与固定输入脚本 | 防止界面与学习功能拖慢输入 |
| 丢字 / 重复上屏 / 错删次数 | 自动回放与真机回归 | 发布阻断条件 |
| 释义覆盖率、释义阅读任务成功率 | 数据集统计与主动查看任务 | 判断英语特色是否带来实际价值 |

建议按三个里程碑推进：

1. **可靠性验收**：R01–R07。先建立真机基线、补回归、接入本地学习与隐私开关，达到稳定发布门槛。
2. **日常效率优化**：U01–U10、I01–I03、L01 / L03。先用任务观察决定触控与候选改进，再交付设置、光标、符号和词库能力。
3. **学习与扩展**：L02、E01–E04。按使用价值与实现成本逐项评审，保留离线输入与关闭入口。

每个需求都按“复现或测量 → 实现 → 针对性验证 → 完整回归”完成；每次交付附已实现列表、测试环境、结果、已知限制和覆盖升级检查。
